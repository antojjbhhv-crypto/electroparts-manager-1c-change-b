# Security remediation addendum — audit-remediation

**Исходная ветка:** `main`  
**Исходный коммит:** `0fe671baacc7c491c8bce99c5bf6d486f7dd451d`  
**Статус:** `REMEDIATION_CANDIDATE_NOT_RUNTIME_VERIFIED`  
**Назначение:** подготовка исправлений для отдельной ветки; не является новым релизом и не изменяет тег `v1.1.0-change-b`.

## 1. Обнаруженные расхождения

1. Опубликованная роль `Korrektur` предоставляла `Update` для `AccumulationRegister.Bestaende` и `InformationRegister.KorrekturJournal`. Это противоречит согласованной модели: пользователь читает регистры, но не изменяет их напрямую.
2. Опубликованный код при повторном `OperationID` сравнивал только `Компонента` и `Изменение`. `Причина` и `Пользователь` не входили в проверку идентичности запроса.

## 2. Изменения-кандидаты в этой ветке

### 2.1. Права регистров

В `Roles/Korrektur/Ext/Rights.xml`:
- для `AccumulationRegister.Bestaende` оставлены `Read` и `View`, прямой `Update` удалён;
- для `InformationRegister.KorrekturJournal` оставлены `Read` и `View`, прямой `Update` удалён;
- права чтения справочника компонентов, использования обработки и записи/проведения документов сохранены.

Запись `KorrekturJournal` предполагается выполнять только из серверной функции обработки через узкий helper `ЗаписатьЖурналВПривилегированномРежиме`. Helper:
- включает привилегированный режим непосредственно перед одной записью менеджера регистра;
- выключает его сразу после записи;
- при исключении выключает режим и повторно выбрасывает исключение;
- сохраняет ранее включённый режим, если helper был вызван из уже привилегированного контекста.

Чтение журнала и расчёт остатка выполняются вне этого привилегированного участка.

Для `Bestaende` чтение остаётся обычным. Проведение `Wareneingang` и `Verbrauch` в метаданных имеет `PostInPrivilegedMode=true`; это необходимо проверить в целевой базе с ролью без `Update` у регистра.

### 2.2. Полный payload для повторного OperationID

При первом вызове имя пользователя вычисляется один раз и используется как при резервировании, так и при сравнении повтора.

Сравниваются:
- `Компонента`;
- `Изменение`;
- `Причина`;
- `Пользователь`.

Не сравниваются серверная дата корректировки, статус результата и ссылка на компенсирующий документ: это поля результата/учёта, а не входного payload.

При отличии любого из четырёх полей повтор должен завершаться ошибкой несовпадения payload без создания второго документа или движений.

## 3. Что не менялось

- `DataProcessor.Korrektur` metadata и форма;
- `Wareneingang` и `Verbrauch` modules;

## 4. Обязательная проверка на 1C:Enterprise 8.3.27.1508

Эта ветка **не считается runtime-проверенной**. До слияния обязательны проверки в отдельной копии базы:

1. Загрузка конфигурации и `/CheckModules`.
2. Вход пользователем, которому назначена только роль `Korrektur` (плюс минимальные базовые права, требуемые платформой).
3. Чтение `Bestaende` для расчёта остатка и чтение `KorrekturJournal` для поиска существующего UUID.
4. Успешное резервирование новой записи журнала и обновление той же записи до `Проведено` при отсутствии прямого `Update` у регистра.
5. Прямое изменение `Bestaende` и `KorrekturJournal` пользователем роли должно быть отклонено.
6. Проведение `Verbrauch` и `Wareneingang` должно создавать движения при отсутствии прямого `Update` у `Bestaende`.
7. Повтор с полностью тем же payload возвращает исходный документ.
8. Поочерёдно изменить компоненту, количество, причину и пользователя при том же UUID: каждый такой повтор должен быть отклонён; новые документы и движения отсутствуют.
9. Проверить, что `ПривилегированныйРежим()` возвращает исходное состояние после успешной записи журнала и после искусственного отказа записи.
10. Повторить T-F: ошибка после проведения документа, но до завершения записи журнала, должна откатить резервирование, документ и движения.

Отдельно документировать, что роль по-прежнему имеет права `Insert/Update/Posting` на документы. Этот кандидат не меняет эту часть модели доступа; если требуется запрет прямого создания/проведения документов вне `Korrektur`, это отдельное решение и изменение области работ.
