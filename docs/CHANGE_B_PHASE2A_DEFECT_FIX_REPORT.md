## 4. Служебная особенность загрузки

`/LoadConfigFromFiles` пропускает изменённые `.bsl`, если актуальный `ConfigDumpInfo.xml` описывает объект как неизменённый: первая загрузка прошла с `exit=0`, но модуль в ИБ остался прежним. Принудительная полная загрузка выполнена переносом `ConfigDumpInfo.xml` в `backup\ConfigDumpInfo_pre_forced_load.xml` (SHA-256 `71208C18…`). После выгрузки `ConfigDumpInfo.xml` создан заново.

Отдельно зафиксировано: контрольная выгрузка из ИБ перезаписывает файлы в `work-config`, поэтому патч накладывается только после выгрузки и непосредственно перед загрузкой.

## 5. Состояние формы `DataProcessor.Korrektur.Форма`

Точка запуска собрана и подтверждена контрольной выгрузкой из `test-ib` (`dump_after_form2`):

- реквизиты: `Объект`, `OperationID` (`v8:UUID`), `Компонента` (`CatalogRef.Komponenten`), `Причина` (Строка 500), `Изменение` (Число 15.3) — `Реквизит1` (Строка 0) заменён на `Причина`;
- элементы формы: поля ввода `Изменение`, `Компонента`, `OperationID`, `Причина` и кнопка `КнопкаВыполнить` (`UsualButton`);
- команда `Выполнить` с `Действие = Выполнить`;
- модуль формы `Forms\Форма\Ext\Form\Module.bsl`: `&НаКлиенте Выполнить(Команда)` → `&НаСервере ВыполнитьНаСервере()` → `Объект.ВыполнитьКорректировку(OperationID, Компонента, Изменение, Причина)`, результат выводится через `Сообщить`.

Два последних недостающих элемента — `InputField` для `OperationID` вместо `LabelField` и кнопка команды — внесены правкой `Form.xml` в `work-config` с последующей загрузкой из файлов (решение владельца, вместо ручной сборки в Конфигураторе). Платформа отработала без падения: `exit=0`, обновление конфигурации и `/CheckModules` успешны, обратная выгрузка совпала побайтно.

Поведенческий прогон сценариев не выполнялся.
