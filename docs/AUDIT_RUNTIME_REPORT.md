## 4. Что подтверждено статически

- `Rights.xml`: `AccumulationRegister.Bestaende` — только `Read/View`; `InformationRegister.KorrekturJournal` — только `Read/View`; документы `Wareneingang` и `Verbrauch` — `Read/Insert/Update/Posting/View`.
- `OperationID` — измерение регистра (строка 361 `KorrekturJournal.xml`), поэтому повторная запись с тем же ключом отклоняется платформой; на этом построена идемпотентность.
- `PostInPrivilegedMode=true` и `UnpostInPrivilegedMode=true` для обоих документов.
- Модуль: сравнение payload включает `Компонента`, `Изменение`, `Причина`, `Пользователь`; helper `ЗаписатьЖурналВПривилегированномРежиме` сохраняет и восстанавливает признак привилегированного режима в успешной и исключительной ветках.

## 5. Найденная проблема (не исправлялась)

Роль `Korrektur` не содержит прав запуска клиента (`ThickClient`, `ThinClient`, `MainWindowMode*`). Пользователь, которому назначена только эта роль, не может запустить ни толстый, ни тонкий клиент — подтверждено диалогами платформы.

**Минимальное исправление (предложение, не применено):** назначить пользователю дополнительную базовую роль с правами запуска клиента либо добавить эти права в отдельную служебную роль, не меняя `Korrektur`. Решение требует отдельного согласования.

## 6. Ограничения и открытые риски

- Рантайм-проверки не выполнены; пункты 2–7 остаются неподтверждёнными.

- Тестовая обвязка (создание пользователей, пробы, обход прав) существовала только в копии конфигурации и в ветку не входит.
